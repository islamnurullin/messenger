# ADR 0004. JWT хранится в localStorage

**Статус:** принято
**Контекст:** этап 2, авторизация в веб-клиенте

## Вопрос

Браузерный клиент получает от бэкенда пару токенов: `access` (15 минут) и `refresh`
(30 дней). Где их хранить?

| Вариант | Плюсы | Минусы |
|---|---|---|
| `localStorage` | Просто, работает кросс-доменно, не нужен CSRF | Доступен из JS — при XSS токен утекает |
| `httpOnly`-cookie | XSS не читает токен | Нужны CSRF-токены, `SameSite`, прокси для :5173→:8000, CORS с `credentials` |
| Память (in-memory) | Не переживает перезагрузку — XSS-окно короче | Пользователь входит заново на каждой вкладке; нужно хранить refresh отдельно |

## Решение

`localStorage`, ключи `messenger.access` и `messenger.refresh`.

## Обоснование

1. **Главный риск `localStorage` — XSS, и в этом приложении его почти нет.** Весь
   пользовательский текст (сообщения, имена) рендерится через шаблоны Svelte,
   которые экранируют HTML. Мессенджер на этапах 1–7 не принимает HTML от
   пользователя — только plain text.
2. **Cookie-схема добавляет три подсистемы сразу** — CSRF, доменную настройку и
   прокси для разработки. Для одного разработчика на учебном проекте это
   стоимость без выгоды: атакующий, способный выполнить JS на странице, обычно
   может и отправить запрос от имени пользователя, даже с cookie.
3. **Кросс-доменная разработка.** Фронт на `:5173`, бэкенд на `:8000`. Cookie с
   `SameSite=Lax` в эту схему не встают без прокси; `SameSite=None` требует
   `Secure` и HTTPS локально, то есть самоподписанного сертификата.

## Последствия

- При XSS токен утекает — как и при cookie-схеме, если атакующий может делать
  запросы от лица пользователя. Митигация — не XSS-уязвимости, а не выбор
  хранилища.
- `access` живёт 15 минут; при 401 клиент один раз обновляет его по `refresh`
  (см. `web/src/lib/api/client.ts`), параллельные запросы ждут общий промис.
- Выход очищает оба ключа и рассылает событие `messenger:auth`, чтобы открытые
  вкладки синхронизировались.
- Если на этапе 10 (Electron) понадобится хранение вне веб-контекста, токены
  переедут в `safeStorage` Electron — это то же самое решение, но с шифрованием
  на диске.

## Пересмотр

Пересмотреть, если: появится рендеринг пользовательского HTML (markdown,
вставки), или если аудит покажет XSS, или если понадобится SSO с внешним
провайдером.
